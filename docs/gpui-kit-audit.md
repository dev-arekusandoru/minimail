# gpui-kit 0.7 adoption audit

**Status: migration complete.** Every component below marked *Used* is adopted across the app (the rest are *N/A*, *Kept*, or row-like divs deliberately left); the visual and behavioural losses from adopting them are listed under [Adopted — known losses](#adopted--known-losses) at the end.

Scope: `gpui-component-0.7.0/src` (re-exported as `gpui_kit::component`) plus `gpui-kit-0.7.0`. The gpui-kit.com index was not consulted; everything below is verified against the crate source and this repo's `src/`/`tests/`. Audit only: no source was changed.

## Findings worth calling out

1. **Dialog split.** Two modal systems coexist: kit `Dialog` (palette, folder picker, confirms) and the legacy `overlay()` stack (snooze, settings, rules, ChoiceDialog, help). Finishing the move is the single biggest consistency win and lets us delete `overlay.rs`.
2. **Toast.** Custom absolute-positioned div; `Root` already mounts the notification layer, so `push_notification` is available.
3. **Menus.** `MenuPanel` duplicates `PopupMenu` including keyboard nav and Kbd rendering.
4. **Pills.** Four independent hand-rolled pills: reader badges, list chips, sidebar count, row account dot.
5. Tooltips, Kbd, Tab, Command, StatusBar, Resizable are already consistent: every tooltip site builds the kit `Tooltip`.

## Adopted — known losses

- D2: filter chips are the kit `Button` (`outline().xsmall().selected(on)`), not the old hand-rolled pill: kit outline/selected colours replace the `primary` border + `list_active` fill, padding is `px_1`, and the label is the kit xsmall `text_xs` (12px) rather than 11px. Ids (`("chip", i)`) and click behaviour are unchanged.
- D2: the sidebar count pill is a kit `Tag` (chosen over `Badge`, whose count renders as an absolutely-positioned floating overlay, not an inline count). `Tag` fixes the text at `text_xs` (12px vs the old 10px), gains a 1px border tinted like the fill, and has a built-in `hover` dimming — so a count label now dims when the pointer is over it even though it is not interactive. Highlighted (active-row) vs muted fills are preserved via `Tag::custom`. The `account-count-*` id now sits on a wrapper div (Tag has no `id`).
- D2: the "no mail / no matches" list empty state is the kit `Empty`, which paints a dashed rounded border, `p_6` around centred content, and a foreground-coloured title — the old state was bare muted text.
- D2: the sidebar, reader, help body and rules list gained overlay scrollbars. The reader and help keep their `ScrollHandle` (find / jump-to still work) via `.vertical_scrollbar(&scroll)`; the sidebar and rules panel use the wrapper's own handle.
- D1: the reader monogram is now the kit `Avatar`: circular and tinted from a hash of the initials, where the old monogram was a bordered rounded square in the muted colour. We keep `reading::initials` by feeding the avatar that string as its `name`, so the glyph text is unchanged (and the `reader-tab-avatar` id sits on a wrapper div, since `test_support` does not accept `Stateful<Avatar>`).
- D1: reader tag badges are the kit `Tag` (same mono text, tint/`px(6)`/`h(18)`/4px radius kept via `Styled` overrides). `Tag` has a built-in hover dim on what is not an interactive control, and no icon slot, so a glyph is still a child.
- D1: `recipient_rows` is a `DescriptionList` under a `Separator`: it draws a label column on the description-list label background, and values are the list's `text_sm` (14px) rather than the old plain 12px row text.
- D1: the composer's read-only To/Subject header is one `DescriptionList` (`columns(1)`, `label_width(56)`, `bordered(false)`) like `recipient_rows`, replacing two hand-rolled label/value rows; its labels take the description-list label colour instead of the composed row's `muted_foreground`, and it loses the kit `Label` wrapper on the values.
- D1: the new-sender and possible-spam banners are kit `Alert`s (`warning` / `error`), which replace the app's accent/new-sender and spam colours with the theme's variant colours and add a leading icon; the action buttons sit beside the alert because `Alert` has no action slot.
- D1: `panels.rs` `RuleBanner` is a kit `Alert::info(..).banner()` inside the same bottom-bordered strip, so its `primary @ 10%` fill becomes the info variant fill and it gains a leading icon; its action buttons sit beside the alert.
- D1: `panels.rs` `SessionCard` shows the session position as a kit `Progress` bar instead of the `"{pos}/{total}"` text; the number survives only as the bar's accessibility label.
- **WS-A:** Dialogs slide in over 250ms; controls move during that time, so a click aimed at one before the animation ends can miss. Headless tests wait the animation out (`settle` in the UI test harnesses), and a keystroke typed in the same batch as the key that opens a dialog (`s 4`) reaches the app before the dialog is focused.
- **WS-A:** The backdrop is the kit's overlay colour, not our `bg @ 85%`, and dialogs sit a tenth of the viewport down with the kit's own width/height clamping; the old `min(80px, 10%)` offset and `FitViewport` sizing are gone (`overlay.rs` deleted).
- **WS-A:** `escape` and backdrop clicks are owned by the kit `Dialog`; the `SnoozeCancel`, `DialogCancel`, `SettingsClose` and `RulesClose` actions and their bindings no longer exist, and cancelling emits no event (the owner just forgets the view in `dialog_dismissed`).
- **WS-A:** The kit's `enter` → confirm is disabled (`on_ok(|..| false)`): an `enter` that propagates out of the snooze input would otherwise close the dialog and drop the picker before its `PressEnter` event ran.
- **WS-A:** The help view is a `HelpPanel` entity with its own key context: `pageup`/`pagedown`/`j`/`k`/arrows/`?` are bound under `HelpPanel` instead of being intercepted by `MailApp`, so they only scroll while the help dialog is focused.
- F: thread messages are a kit `Collapsible` driven by the app's disclosure state (`Collapsible::open(bool)`, no `motion_id` so find-driven expansion does not desync the scroll offsets). An expanded thread message now keeps its compact summary line as the collapsible trigger above the full body, where before expansion replaced the line with the surface outright.
- F: the expanded thread message's header id changed from `("reader-thread-msg", id)` to `("reader-thread-head", id)`, so the collapsible trigger (`("reader-thread-msg", id)`) and the expanded surface can coexist for the tests without a duplicate id.
- F: the quoted-text fold is a kit `Collapsible`; its `SHOW/HIDE QUOTED TEXT` link is the trigger and the indented quoted block is the content.
- F: the reader avatar feeds `reading::initials` to the kit `Avatar` as space-separated single letters, because the kit's own derivation takes the first letter of each word with a byte-counted one-letter fallback, which would otherwise truncate two-letter non-ASCII initials (e.g. `ŁŻ`).
- F: the sidebar is the kit `Sidebar` with `SidebarMenuItem` rows (`SidebarCollapsible::None`, so our `Resizable` and `cmd-b` remain the only width/visibility owners). Lost: the folder tree rails, the per-account active-marker colour bar, the fold-on-hover chevron, and the separate scrollbar D2 added (the kit sidebar scrolls its own list without a visible bar). Location icons keep their tints via `Icon::text_color`.
- F: account and folder folding are now the kit submenu's, opened by its own caret. - F: sidebar rows carry the kit's generated ids (top-level items are integer indices `0`, `1`, …; nested items are `"<parent>-<child>"`), so the `nav-*` / `account-*` ids are gone and `tests/ui_nav.rs` (plus one click each in `tests/ui_ext/rules_new_senders.rs` and `tests/ui_ext/outbox_classifier.rs`) were rewritten. A submenu parent's element spans its children, so a centre click targets the child; tests click leaf rows.
- **WS-B:** The toast is a kit `Notification` card (popover background, border, shadow, success icon, 382px wide, 400ms slide) instead of our solid success-green pill; it is placed bottom-centre per notification (`Anchor::BottomCenter`, bottom margin 40px set in `theme::apply`) and has a hover close button. The fixed 4s `TOAST_MS` timer is gone; the kit's autohide owns the duration.
- **WS-B:** The Undo button sits on its own line under the message (a `Notification::content` row) rather than inline, because `Notification::action` would disable autohide. It keeps the `u` keycap tooltip and dismisses the toast when clicked.
- **WS-B:** `MailApp::toast` is no longer what is painted: it mirrors the visible text (cleared from `Notification::on_close` if no newer toast replaced it) so headless tests can read it, since the kit keeps the notification message private.
- **WS-C:** The `MenuPanel` is gone; the `⋯`, More and Filter ▾ menus are the kit `PopupMenu` in a `Popover` anchored `TopRight` to the trigger. Our fixed 224px width, 24px/12px rows, hand-estimated height clamp and `‹ Back` row are replaced by the kit's sizing, 26px `text_sm` rows and its own submenu flyout (opened by hover or `right`, left/`escape` to go back); `backspace` no longer goes back a level.
- **WS-C:** A click outside an open menu dismisses it, but there is no backdrop any more, so the click also reaches whatever is underneath (before, the backdrop swallowed it).
- **WS-C:** Each row's keycap is the kit's lookup of the action's binding from the trigger's focus path, not our documented `key` string, so a row whose action has no binding in reach shows no keycap. Active filter choices use the kit check icon instead of a `✓ ` text prefix, and an open trigger uses `Button::selected` instead of a `list_active` background.
- **WS-C:** `j`/`k` still move the highlight (bound to the kit's `SelectDown`/`SelectUp` under `PopupMenu`); every other bare list key is inert while a menu is open because `MailApp` drops its key context (`menu_open`, mirrored from the popover's open-change).
- **WS-C:** Menu rows have no element ids (`btn-archive`, `filter-clear`, …): headless tests find rows by label through `tests/common/menu.rs`. A menu with nothing to offer is no longer suppressed (no existing trigger can produce one).
- **WS-E:** The titlebar is the kit `TitleBar` (`src/app/mail_app/titlebar.rs`, window options from `TitleBar::window_options()`), so the bar is 34px tall (was 36px), uses the theme's `title_bar` / `title_bar_border` colours with the kit's top-to-bottom blend (was `sidebar` + `border`), and gains the kit's Windows/Linux window controls. Our own drag-region state and double-click handling are deleted in favour of the kit's.
- **WS-E:** The kit's left inset is overridden to zero (`pl_0`) so the left region keeps the traffic-light clearance; the cost is that this app still owns the 80px-on-macOS / 12px-elsewhere inset instead of using the kit's constant. The search box is an overlay across the whole bar (centred on the window, with `SEARCH_SIDE` kept clear on each side), so on a narrow window it shrinks before it would touch the title or buttons, and the left title can be clipped earlier than before.
